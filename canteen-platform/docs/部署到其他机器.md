# 食堂管理数据平台 — 部署到其他机器操作说明

> 本项目是**前后端不分离**的单体应用：前端页面已编译进 `canteen-platform.jar`，目标机器只需运行这一个 jar + 一个 MySQL 数据库即可，**无需**安装 Node / 前端构建工具 / 单独部署前端。

---

## 一、需要从源机拷贝的东西

| 内容 | 位置 | 说明 |
|---|---|---|
| **应用 jar** | `backend\target\canteen-platform.jar`（约 43MB） | 已包含全部前端页面，唯一要运行的程序 |
| **上传图片目录** | `backend\uploads\` | 菜品图片等上传文件，**必须一并拷贝**，否则页面图片丢失 |
| **初始化 SQL** | `sql\init.sql` | 建表 + 种子数据，仅**全新空部署**时用 |
| **现有数据库数据** | MySQL `canteen` 库（11 张表） | 用 `mysqldump` 导出迁移，**保留你现有全部数据** |
| （可选）**便携 MySQL** | `tools\mysql-8.0.37-winx64` | 目标机不想另装 MySQL 时可携带，含 `mysql-data` 数据目录 |

---

## 二、目标机器环境要求

| 软件 | 版本 | 说明 |
|---|---|---|
| JDK | **17**（必须） | jar 用 JDK17 编译，版本过低会报 `UnsupportedClassVersionError` |
| MySQL | 8.0 | 存储数据。可用系统已装的，也可用项目便携版 |
| 操作系统 | Windows / Linux 均可 | jar 是跨平台 Java 程序 |

> 目标机**不需要**：Node.js、npm、Maven、前端框架 —— 打包产物里已全部包含。

---

## 三、安装目标机软件

### 方式 A：目标机自己装 JDK 17 + MySQL 8
1. 安装 **JDK 17**（如 `Temurin 17` / `Oracle JDK 17`），并记住安装路径。
2. 安装 **MySQL 8.0**，创建数据库账号（默认 `root/root`），并记住端口（默认 3306）。
3. 若 MySQL 账号/密码/端口与默认不同，见本文「六、数据库连接配置」。

### 方式 B：复用项目自带的便携 MySQL（可选，免安装）
把源机 `tools\mysql-8.0.37-winx64` 整个目录拷贝到目标机。数据目录 `mysql-data` 需一并拷（它存着库数据）。启动方式见项目 `docs\安装工具指引.md`。

---

## 四、迁移数据库数据（关键：保留现有全部数据）

> 你现有菜品、食材、价格、周食谱等数据都在 MySQL 的 `canteen` 库中，迁移用 `mysqldump` 完整导出再导入，**不会丢失任何数据**。

### 步骤 1：在源机导出备份
用源机的 MySQL 自带 `mysqldump`（项目便携版在 `tools\mysql-8.0.37-winx64\bin\mysqldump.exe`）：

```
mysqldump -uroot -proot --databases canteen > D:\canteen-backup.sql
```

- 得到 `canteen-backup.sql`（含建库、建表、全部数据）。
- 也可顺带用同命令在**导出后**保留此文件作为备份。

### 步骤 2：拷贝到目标机
把 `canteen-backup.sql` 复制到目标机器任一目录（如 `D:\`）。

### 步骤 3：在目标机导入
```
mysql -uroot -proot < D:\canteen-backup.sql
```

> 若目标机是**全新空部署**（不要旧数据），改为执行初始化 SQL：
> ```
> mysql -uroot -proot -e "CREATE DATABASE canteen DEFAULT CHARACTER SET utf8mb4;"
> mysql -uroot -proot canteen < sql\init.sql
> ```

## 五、放置应用并启动

### 1. 放置文件
在目标机建一个工作目录，例如 Windows `D:\canteen-platform`（或 Linux `/opt/canteen`）：
- 放入 `canteen-platform.jar`
- 新建 `uploads` 子目录，把源机 `backend\uploads` 里的图片全部拷进去
  > 程序把图片写到"当前工作目录下的 `uploads`"，上传路径存的是 `/upload/xxx`，所以**必须**有 uploads 目录且内容与源机一致。

### 2. 启动

**Windows（命令行）**：
```
cd /d D:\canteen-platform
"完整路径\bin\java.exe" -jar canteen-platform.jar
```
示例（若 JDK17 装在 D 盘）：
```
cd /d D:\canteen-platform
"D:\work soft\jdk17\bin\java.exe" -jar canteen-platform.jar
```

**Linux**：
```
cd /opt/canteen
nohup /usr/bin/java -jar canteen-platform.jar > app.log 2>&1 &
```

### 3. 访问
浏览器打开 `http://目标机器IP:8080`，标题显示「食堂管理数据平台」。

> 窗口关闭后程序会退出。Windows 想后台常驻可用 `start /b`，或用脚本 `start-all.bat` / `restart.bat`（需按目标机路径调整）。

## 六、数据库连接配置（目标机 MySQL 与默认不同时）

程序默认连接 `localhost:3306/canteen`，账号 `root/root`。若目标机不同，**无需改代码**，用环境变量覆盖即可：

**Windows（先 set 再启动）**：
```
set MYSQL_HOST=127.0.0.1
set MYSQL_PORT=3306
set MYSQL_USER=root
set MYSQL_PASSWORD=你的密码
java -jar canteen-platform.jar
```

**Linux**：
```
export MYSQL_HOST=127.0.0.1
export MYSQL_PORT=3306
export MYSQL_USER=root
export MYSQL_PASSWORD=你的密码
java -jar canteen-platform.jar
```

| 环境变量 | 作用 | 默认值 |
|---|---|---|
| `MYSQL_HOST` | 数据库地址 | localhost |
| `MYSQL_PORT` | 数据库端口 | 3306 |
| `MYSQL_USER` | 数据库用户 | root |
| `MYSQL_PASSWORD` | 数据库密码 | root |

---

## 七、部署后验证

1. 浏览器打开 `http://目标机IP:8080`，确认页面正常加载、标题正确。
2. 检查**菜品库 / 食材价格 / 周食谱 / 采购汇总**等数据是否与源机一致（含图片、价格、配料、菜品图片）。
3. 新增一个菜品并上传图片，确认 `uploads` 目录能正常写入。

---

## 八、常见问题

| 现象 | 原因 / 解决 |
|---|---|
| 启动报 `UnsupportedClassVersionError` | JDK 版本低于 17，装 JDK 17 |
| 打不开页面 | 8080 端口未放行防火墙，或未监听（`netstat -ano | findstr 8080`） |
| 图片不显示 | `uploads` 目录未拷贝或未放在 jar 同一工作目录下 |
| 连接数据库失败 | 数据库未启动 / 账号密码不对，用第六节环境变量覆盖 |
| 数据是空的 | 未导入 `canteen-backup.sql`（或 init.sql），见第四节 |

---

## 九、每次改动代码后的重新部署（如目标机需要新功能）

若你在源机改代码并重新打包出新的 `canteen-platform.jar`，目标机**只需替换 jar**（停掉旧进程 → 拷贝新 jar → 重新启动），数据库和 uploads 目录**不要动**，数据全部保留。
