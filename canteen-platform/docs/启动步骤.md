# 食堂管理数据平台 — 启动步骤说明

## 快速启动（推荐，一条命令）

在项目根目录已提供一键启动脚本：`start-all.bat`（双击即可，依次启动 MySQL → 后端 → 打开浏览器）。

---

## 详细启动步骤（分步）

### 第 1 步：确保 MySQL 已启动

```powershell
$mysql = "D:\canteen-platform\tools\mysql-8.0.37-winx64"
$data  = "D:\canteen-platform\tools\mysql-data"
Start-Process "$mysql\bin\mysqld.exe" -ArgumentList "--no-defaults","--basedir=$mysql","--datadir=$data","--port=3306","--console" -WindowStyle Hidden
```

验证：`& "$mysql\bin\mysql.exe" -uroot -proot -e "SELECT 1;"` 返回 `1` 即正常。
（数据库 `canteen` 已由 `sql/init.sql` 建好并含种子数据。）

### 第 2 步：启动后端 Spring Boot

方式 A（开发运行，推荐）：
```powershell
cd D:\canteen-platform\backend
mvn spring-boot:run
```

方式 B（打包后运行 jar，最快）：
```powershell
cd D:\canteen-platform\backend
mvn -DskipTests package
java -jar target/canteen-platform.jar
```

后端默认端口 **8080**，连接本机 MySQL `canteen` 库（root/root）。

### 第 3 步：构建前端（仅在改动前端代码后需要）

前端已构建完成并打包进后端（`backend/src/main/resources/static`）。若修改了前端源码需重新构建：

```powershell
cd D:\canteen-platform\frontend
npm install          # 仅首次
npm run build        # 输出到 backend/src/main/resources/static
cd ..\backend
mvn -DskipTests package   # 重新打包，使前端进入 jar
java -jar target/canteen-platform.jar
```

### 第 4 步：访问

浏览器打开 <http://localhost:8080> 即可使用全部功能。

## 生产部署（Nginx，可选）

前端为纯静态产物（`backend/src/main/resources/static` 目录，构建后即为独立可部署静态文件），后端可仅暴露 API：

1. 将 `backend/src/main/resources/static` 复制到 Nginx 站点目录（如 `/usr/share/nginx/html`）。
2. 配置 Nginx 将 `/api`、`/upload` 反向代理到后端 8080：
```nginx
server {
    listen 80;
    server_name your-domain;
    root /usr/share/nginx/html;      # 前端静态目录
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    location /api { proxy_pass http://127.0.0.1:8080; }
    location /upload { proxy_pass http://127.0.0.1:8080; }
}
```

## 修改代码后如何重启

修改了**前端**（`frontend/src`）或**后端**（`backend/src`）源码后，必须**重新构建并重启**后端才会生效。项目提供两个脚本（双击即可，脚本为纯 ASCII，界面提示为英文）：

| 脚本 | 用途 |
|------|------|
| **`restart.bat`** | **快速重启**：停止 8080 端口上的旧后端进程 → 用 JDK17 重新启动现有 jar。适用于**代码未改动**（只改了配置、或把服务停掉后想再启动）的场景。 |
| **`rebuild-restart.bat`** | **完整重建重启**：停旧进程 → `npm run build` 构建前端 → 重新生成默认分类图片 → `mvn package` 打包后端 → 启动。**只要改了任何前端/后端代码，就用它。** |

两个脚本都会：
1. 先按端口 **8080** 清理旧的后端进程（`netstat + taskkill`），避免出现多个后端实例争用端口、上传目录不一致；
2. 使用 **JDK17 绝对路径** `D:\work soft\jdk17\bin\java.exe` 启动 `backend\target\canteen-platform.jar`（避免解析到系统里另一个 Oracle javapath 的 java，从而产生残留进程）。

手工等价命令（不依赖脚本）：
```powershell
# 1) 停掉 8080 占用进程
cmd /c "for /f ""tokens=5"" %p in ('netstat -ano ^| findstr :8080 ^| findstr LISTENING') do taskkill /f /pid %p"

# 2) 改了前端才需要构建前端
cd D:\canteen-platform\frontend
npm run build

# 3) 重新打包后端（改了后端或前端后都需打包，使前端进入 jar）
cd D:\canteen-platform\backend
mvn -q -DskipTests package

# 4) 启动（必须在 backend 目录，保证上传目录 uploads 相对路径正确）
Start-Process "D:\work soft\jdk17\bin\java.exe" -ArgumentList "-jar","target\canteen-platform.jar" -WorkingDirectory "D:\canteen-platform\backend" -WindowStyle Hidden
```

> 补充：`kill-backend.ps1` 是纯 ASCII + UTF-8 BOM 的进程清理脚本（按命令行包含 `canteen-platform.jar` 匹配），`restart.bat` 等脚本未直接依赖它，保留作手工清理后端进程用。

## 常见问题

- **Access denied for user 'root'@'localhost'**：MySQL root 密码非 `root`，在 `application.yml` 修改或设置 `MYSQL_PASSWORD` 环境变量。
- **3306 被占用**：本机已有 MySQL，改用其 3306；或修改 MySQL 端口与 `application.yml` 保持一致。
- **8080 被占用**：修改 `application.yml` 的 `server.port`。
- **导入 Excel 中文乱码**：请使用 `.xlsx` 文件，列名与模板保持一致（导出可作模板）。
